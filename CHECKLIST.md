## Роли (для команды из 3–4 человек)
| Роль | Отвечает за |
|---|---|
| ML-лид | валидация, модели, итоговая метрика |
| Data / Feature | EDA, фичи, анализ ошибок, проверка утечек |
| Backend / Demo | API, Streamlit, Docker, деплой |
| Product / Pitch | бизнес-ценность, презентация, расчёт эффекта в тенге, репетиция защиты |

Один человек может совмещать роли, но **за презентацию должен отвечать кто-то конкретный с первого дня**.

## Во время хакатона
- [ ] Первый сабмит в первый час (baseline), потом улучшения
- [ ] Каждый эксперимент — с `--tag`, результаты смотреть в `reports/experiments.csv`
- [ ] Коммитить часто, мелкими кусками; работать в ветках, мержить в `main` только рабочее
- [ ] Доверять CV, а не публичному лидерборду (на нём легко переобучиться)

## Ловушки банковских данных
- **Утечки**: признаки «из будущего» (статус после выдачи кредита, дата закрытия), ID, коррелирующие с таргетом; признак с корреляцией 0.99 — почти всегда утечка
- **Несколько строк на клиента** → `--group client_id`, иначе CV завышен
- **Сдвиг во времени** → `--time-col`; adversarial AUC > 0.7 в EDA — тревожный сигнал
- **Дисбаланс** (дефолтов/фрода 1–5%) → AUC/PR-AUC вместо accuracy, подбор порога, stratified CV
- **Форматы**: даты `dd.mm.yyyy`, разделитель `;`, запятая как десятичный разделитель (`pd.read_csv(..., decimal=",")`), кодировка `cp1251`
- **Тексты**: смесь русского и казахского, транслит, опечатки → char n-граммы (`src/text_baseline.py`), мультиязычные модели (multilingual-e5, LaBSE, XLM-R)
- **Персональные данные**: не коммитить датасет, не отправлять реальные данные клиентов во внешние LLM API без разрешения организаторов

## Что ценит банковское жюри
1. **Понятная бизнес-проблема и эффект в деньгах**: «снижаем дефолты на X% → экономия ~N млн ₸ в год», «оператор тратит на 30% меньше времени»
2. **Объяснимость**: почему модель отказала клиенту (SHAP, топ-причины). В банке это требование регулятора, а не украшение
3. **Работающее демо** вживую (и записанное видео на случай, если что-то упадёт)
4. **Путь к внедрению**: куда встраивается (CRM, скоринговый конвейер, колл-центр), какие данные нужны, latency, мониторинг дрейфа
5. Метрика — важна, но +0.003 AUC редко побеждает хорошую историю с демо

## Структура презентации (5–7 минут)
1. Проблема (1 слайд, с цифрой)
2. Решение в одном предложении + скриншот демо
3. Как работает (схема: данные → фичи → модель → API → интерфейс)
4. Результаты: метрика на валидации, сравнение с baseline, важные признаки
5. Бизнес-эффект в тенге и для кого
6. Внедрение: интеграция, риски, следующие шаги
7. Команда

Отрепетировать 2 раза с таймером. Подготовить ответы на вопросы: «как поведёт себя на новых клиентах?», «как объясните отказ клиенту?», «что с дрейфом данных?», «сколько стоит инференс?».

## Если кейс про LLM / GenAI (частый формат AI-хакатонов банков)
- Заранее подготовьте рабочий вызов LLM API (ключ в `.env`) и простой RAG: эмбеддинги (multilingual-e5) + FAISS/Chroma + промпт с цитированием источников
- Типичные кейсы: ассистент оператора колл-центра, классификация и маршрутизация обращений, суммаризация, поиск по внутренним документам/регламентам
- Обязательно покажите оценку качества (набор тестовых вопросов + метрика), а не только «красиво отвечает»
- Учтите казахский язык и guardrails (не выдавать персональные данные, отказ на вопросы вне темы)
