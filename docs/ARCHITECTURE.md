# Архитектура (черновик, дополнять)

```
 .mov ──► video_io.iter_frames (10 fps, ресайз 960)
            │
            ▼
      Perception (на каждый кадр)            модели из models/, офлайн
        • люди + трекинг (ByteTrack)          детектор: RT-DETR / D-FINE (Apache-2.0)
        • роль по зоне (кассир/клиент/инкассатор)
        • предметы: деньги, телефон, сумка, ящик
        • поза рук (RTMPose, Apache-2.0)
            │  FrameObs[]
            ▼
      Rule-детекторы (по таймлайну)  ──► Candidate(type, t_start, t_end, t_peak, observed)
            │
            ▼
      Verifier: локальная VLM (опц.)  — подтвердить / отклонить, описать увиденное
            │
            ▼
      rules.yaml → норматив + цитата;  evidence → 1–3 кадра (лица размыты)
            │
            ▼
      JSON по схеме ТЗ ──► API (/api/v1/jobs/{id}) и UI
```

## Принципы

- **Таймкод берётся из трекинга/правил**, а не из VLM: видео-LLM неточно привязываются ко времени.
- **Ссылки на нормативы — только из `configs/regulations.yaml`**, генерация запрещена (критерий 4).
- **Описание = факты** («кассир вышел из зоны рабочего места в 12.4 c, клиент у окна»), без домыслов о намерениях.
- **Устойчивость к ракурсу** (финальное видео снимут под другим углом): зоны не задаются пикселями;
  роли определяются относительно стойки; аугментации; свои съёмки с других углов (разрешено FAQ 7).
- **Время**: бюджет 240 c из 300; при нехватке времени сначала урезается верификация, потом частота кадров.
- **Пропуск хуже ложного срабатывания** (FAQ 16): пороги детекторов настраиваются на полноту, верификатор срезает FP.
- **Лица** не распознаются (FAQ 29), на кадрах-доказательствах размываются.

## Деплой

Свой компьютер или сервер с GPU → `docker compose up` или `make serve` → `cloudflared tunnel --url http://localhost:8000`
даёт публичный HTTPS-URL. Модели работают внутри сервиса, поэтому это не облачный AI-сервис.
Альтернатива: арендованный GPU-сервер (весь стек ваш).
